## 1. Executive Summary & Purpose of This Report

This report provides the **technical handover and operational guidance** for the **SleepCare Dashboard** frontend application. 

The platform was engineered as part of the **European 6G-PATH Consortium (Horizon Europe)** in collaboration with **Linde Homecare France** and the **DISP Laboratory (Université Lumière Lyon 2 / Université Toulouse Capitole)**. Its mission is to resolve the high dropout rate ($40\%\text{--}50\%$ within 90 days) in Continuous Positive Airway Pressure (CPAP) therapy for Obstructive Sleep Apnea (OSA) patients through predictive AI exception triage, multi-sensor telemonitoring, and automated just-in-time multimedia coaching.

## 2. Engineering Methods & Design Paradigms Used

### 2.1 The Universal Polymorphic Module Pattern
Historically, hospital software was developed as separate repositories or siloed web apps (one for doctors, one for patients, one for technicians). This led to duplicated business logic, divergence in metric definitions, and high maintenance costs.

In SleepCare, we engineered the **Universal Module Pattern** ([`src/app/pages/shared/`](file:///c:/Users/mahmed/Downloads/SleepCare-Dashboard/src/app/pages/shared/)):
- Seven core domain modules serve as the **Single Source of Truth**:
  1. [`UniversalBiomarkers.tsx`](file:///c:/Users/mahmed/Downloads/SleepCare-Dashboard/src/app/pages/shared/UniversalBiomarkers.tsx) (SpO2, ODI, Withings vitals, sleep architecture)
  2. [`UniversalCPAP.tsx`](file:///c:/Users/mahmed/Downloads/SleepCare-Dashboard/src/app/pages/shared/UniversalCPAP.tsx) (Usage hours, AHI, 95th-percentile leaks, pressure titration)
  3. [`UniversalAIAnalysis.tsx`](file:///c:/Users/mahmed/Downloads/SleepCare-Dashboard/src/app/pages/shared/UniversalAIAnalysis.tsx) (Dropout risk, AHI drift, patient clustering)
  4. [`UniversalInterventions.tsx`](file:///c:/Users/mahmed/Downloads/SleepCare-Dashboard/src/app/pages/shared/UniversalInterventions.tsx) (Therapy change audit trail & effectiveness tracking)
  5. [`UniversalSurveys.tsx`](file:///c:/Users/mahmed/Downloads/SleepCare-Dashboard/src/app/pages/shared/UniversalSurveys.tsx) (Psychometric PROM scoring and trend analysis)
  6. [`UniversalReporting.tsx`](file:///c:/Users/mahmed/Downloads/SleepCare-Dashboard/src/app/pages/shared/UniversalReporting.tsx) (Clinical compliance certificate generation and PDF export)
  7. [`Directory.tsx`](file:///c:/Users/mahmed/Downloads/SleepCare-Dashboard/src/app/pages/shared/Directory.tsx) (Master cross-role patient database)
- **Polymorphism**: Each module ingests the exact same normalized telemetry model from [`src/app/data/api.ts`](file:///c:/Users/mahmed/Downloads/SleepCare-Dashboard/src/app/data/api.ts), but dynamically adjusts its UI density, controls, and actions based on the current user role:
  - **Physician Mode**: Dense Cartesian charts, clinical reference lines, PDF export toolbars, and prescription action gates.
  - **Technician Mode**: Hardware serial numbers, modem connectivity status, logistics restock triggers, and firmware telemetry.
  - **Patient Mode**: Motivational gamification rings, therapy streak badges, accessible patient-friendly microcopy, and simplified trends.

### 2.2 Exception-Based Clinical Triage & Human-in-the-Loop AI
Instead of requiring clinicians to manually inspect hundreds of compliant patient profiles:
- Telemetry data is parsed against clinical thresholds:
  - **AHI Spike**: $\ge 15.0\text{ events/hour}$
  - **Critical Mask Leak**: $95\text{th-percentile leak rate} \ge 24.0\text{ L/min}$
  - **CPAP Non-Adherence**: $< 4.0\text{ hours/night}$ across a rolling 7-day or 30-day window
  - **Dropout Probability**: $\ge 70\%$ generated by backend ML random forest/gradient boosted models
- When a threshold is breached, the patient is flagged in the physician exception inbox ([`src/app/pages/physician/Home.tsx`](file:///c:/Users/mahmed/Downloads/SleepCare-Dashboard/src/app/pages/physician/Home.tsx)).
- **Human-in-the-Loop Governance**: AI recommendations are never executed autonomously. The [`RecommendationBanner.tsx`](file:///c:/Users/mahmed/Downloads/SleepCare-Dashboard/src/app/components/RecommendationBanner.tsx) requires explicit physician review, allowing the clinician to Accept, Dismiss, or Modify the clinical suggestion.

### 2.3 Reactive In-Memory Caching & Defensive Mock Fallback
- **`useApi` Hook Pattern** ([`src/app/hooks/useApi.ts`](file:///c:/Users/mahmed/Downloads/SleepCare-Dashboard/src/app/hooks/useApi.ts)):
  - Caches API responses in an in-memory `Map` with a 30-second Time-to-Live (TTL).
  - Eliminates duplicate network requests across component remounts and tab switches.
  - Exposes an explicit `invalidateCache()` function used when performing mutations (e.g. submitting surveys or retraining models).
- **Dual-Mode Backend Resilience** ([`src/app/data/api.ts`](file:///c:/Users/mahmed/Downloads/SleepCare-Dashboard/src/app/data/api.ts#L465-L555)):
  - If backend VM2 is unreachable, the frontend can transparently fall back to an offline mock database ([`src/app/data/mockData.ts`](file:///c:/Users/mahmed/Downloads/SleepCare-Dashboard/src/app/data/mockData.ts)).
  - Controlled by the environment flag `VITE_DISABLE_MOCKS=false` (safe fallback) or `VITE_DISABLE_MOCKS=true` (strict live VM verification).

### 2.4 Distributed Tracing & 6G-PATH Telemetry Methodology
To satisfy the scientific research deliverables of the 6G-PATH Consortium, the frontend actively captures interaction timestamps ($t_0$ through $t_{10}$) tracking the lifecycle of an alert from edge hardware to user consumption:
- $t_0$: CPAP / Withings device physiological measurement at the patient's bedside.
- $t_1$: Edge gateway data ingestion.
- $t_2$: Transmission over 5G/6G cellular slice to VM2.
- $t_3$: Telemetry ingestion and database persistence in `DB_Clinical`.
- $t_4$: ML anomaly evaluation and triage rule firing on VM3.
- $t_5$: Notification payload queued for browser push.
- $t_6$: Browser client receives notification or polls triage inbox.
- $t_7$: Clinician opens the alert and views patient record in the browser.
- $t_8$: Clinician initiates educational video prescription or therapy order.
- $t_9$: Patient client receives coaching video notification.
- $t_{10}$: Patient plays the video (Time-to-First-Frame recorded on screen).

To successfully continue the engineering and maintenance of this repository, the incoming intern should possess or develop the following competencies:

### 3.1 Technical & Engineering Competencies
1. **Modern React (v18 / v19) & TypeScript (v5+)**:
   - Deep understanding of React functional components, hooks (`useState`, `useEffect`, `useCallback`, `useRef`, custom hooks), and context.
   - Strict TypeScript: interface discrimination unions, generic API return wrappers (`Promise<ApiResponse<T>>`), and strict null checks.

   - Understanding nested route layouts (`PhysicianLayout` -> `PhysicianPatientLayout` -> Child route).
   - Dynamic parameter extraction via `useParams<{ id: string }>()`.
3. **Data Visualization with Recharts 2**:
   - Constructing multi-axis `ComposedChart` containers (`yAxisId="left"`, `yAxisId="right"`).
   - Injecting SVG `<ReferenceLine />` benchmarks and writing custom SVG tooltip formatters.
   - **Crucial Rule**: Knowledge that Recharts SVG elements cannot consume Tailwind utility classes or CSS `var()`, requiring local hex constants (`CHART_COLORS`).
4. **Tailwind CSS v4 & Design Tokens**:
   - Modern `@import "tailwindcss";` syntax without legacy `tailwind.config.js`.
   - Managing CSS custom properties in `src/styles/theme.css`.
5. **State Management & Network Synchronization**:
   - Polling loops with clean `setInterval` / `clearInterval` lifecycles in `useEffect`.
   - In-memory caching and cache invalidation patterns.
6. **HTML5 Media Player & WebVTT Subtitling**:
   - Controlling `<video>` DOM elements, handling `crossOrigin="anonymous"`, binding `<track>` elements, and calculating microsecond latency KPIs via `performance.now()`.

### 3.2 Clinical & Healthcare Domain Knowledge
1. **Obstructive Sleep Apnea (OSA) & CPAP Therapy**:
   - **AHI (Apnea-Hypopnea Index)**: Normal ($< 5$), Mild ($5\text{--}15$), Moderate ($15\text{--}30$), Severe ($> 30\text{ events/hour}$).
   - **Compliance Standard**: $\ge 4.0\text{ hours/night}$ on at least $70\%$ of nights in a consecutive 30-day period.
   - **Mask Leak**: Intentional exhaust vs unintentional leak. Unintentional leak $\ge 24.0\text{ L/min}$ causes therapy failure and ocular irritation.
   - **Titration Pressure**: Prescribed air pressure measured in $\text{cmH}_2\text{O}$ (typically $6\text{--}16\text{ cmH}_2\text{O}$).
2. **Standardized Patient-Reported Outcome Measures (PROMs)**:
   - **ESS (Epworth Sleepiness Scale)**: Daytime somnolence assessment ($0\text{--}24$ scale; $> 10$ indicates excessive daytime sleepiness).
   - **PSQI (Pittsburgh Sleep Quality Index)**: Comprehensive sleep quality score ($0\text{--}21$).
   - **ISI (Insomnia Severity Index)**: Clinical insomnia severity evaluation ($0\text{--}28$).

## 6. Handover Playbook & Common Scenarios for the Incoming Intern

### Scenario 1: Adding a New Metric to Universal Biomarkers
1. **Update the TypeScript Model**: In [`src/app/data/api.ts`](file:///c:/Users/mahmed/Downloads/SleepCare-Dashboard/src/app/data/api.ts), add the new field to `BiomarkerData` (e.g. `respiratory_rate_bpm?: number[]`).
2. **Update the Data Parser**: In `fetchBiomarkers()` inside `api.ts`, parse the incoming backend JSON into the new interface field.
3. **Register the Metric in the UI**: In [`src/app/pages/shared/UniversalBiomarkers.tsx`](file:///c:/Users/mahmed/Downloads/SleepCare-Dashboard/src/app/pages/shared/UniversalBiomarkers.tsx), add a new selector configuration to the `biomarkerTypes` array (title, unit, icon, and target color).
4. **Add Chart Visual**: Add a corresponding `<Line />` or `<Area />` tag inside the Recharts `<ComposedChart>` container using a defined hexadecimal color.

### Scenario 2: Adding a New Educational Coaching Video
1. **Upload Video Asset**: Place the MP4 video on the dedicated Media Server (`${VITE_VIDEO_URL}/videos/existing/<filename>.mp4`).
2. **Upload Subtitles**: Place the English and French WebVTT files at `${VITE_VIDEO_URL}/subtitles/<filename>.en.vtt` and `.fr.vtt`.
3. **Add Database Entry**: In the backend database table `coaching_videos`, add the clip definition inside the `clips` JSON array with matching URLs and duration.
4. **Verification**: Navigate to `/patient/videos` as a patient and confirm the clip loads, plays, displays subtitles, and advances correctly.

### Scenario 3: How to Test Live VM Mode vs Mock Fallback Mode
- **Offline Mock Testing**: Set `VITE_DISABLE_MOCKS=false` in `.env`. If the backend VM is down, the frontend seamlessly loads data from `src/app/data/mockData.ts`.
- **Strict Live Verification**: Set `VITE_DISABLE_MOCKS=true` in `.env`. Any API error or network failure will throw directly, allowing you to catch backend contract mismatches.

### Scenario 4: Critical Debugging Gotchas to Remember
- **Subtitles fail to load or display**: Ensure the `<video>` element has `crossOrigin="anonymous"`. Without this attribute, the browser blocks cross-origin `.vtt` requests due to CORS security rules.
- **FastAPI returns HTTP 422 Unprocessable Entity on video interaction**: FastAPI's Pydantic model requires `watch_duration_seconds` to be an **integer**. Always apply `Math.round()` before passing the duration to `submitVideoInteraction()`.
- **Withings OAuth fails with redirect error**: Withings rejects plain HTTP IP addresses without a domain name. Testing Withings OAuth requires an HTTPS callback URL (use `ngrok http 80` on the backend VM to generate a temporary HTTPS tunnel).
- **Chart colors do not match CSS variables**: Recharts renders in SVG and cannot resolve Tailwind utility classes or `var(--teal)` custom properties. Always update the local `CHART_COLORS` object in the chart component file.
